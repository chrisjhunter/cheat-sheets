# B2 CLI Cheat Sheet

Backblaze B2 is S3-like cloud object storage. Its CLI (`b2`) has two syntax generations: pre-v4 flat commands (`b2 create-bucket ...`) still work but are deprecated, while v4+ uses `category subcommand` form (`b2 bucket create ...`) plus a `b2://bucket/path` or `b2id://fileId` URI scheme for `ls`/`rm`/`sync`. v4+ flags are kebab-case only (old camelCase flags no longer work under `b2`, though they still work if you invoke `b2v3` explicitly).

## Auth & account
```bash
b2 authorize-account                   # interactive prompt (hides the key when typed - good for screen sharing)
b2 authorize-account <keyId> <appKey>  # authorize in one shot, master or restricted key
b2 account authorize <keyId> <appKey>  # v4+ equivalent
b2 get-account-info                    # show current session's auth token, capabilities, apiUrl, downloadUrl
b2 clear-account                       # invalidate the session token (log out)
```

## Buckets
```bash
b2 list-buckets                       # list bucketId, bucketType, bucketName
b2 bucket list                        # v4+ equivalent
b2 create-bucket mybucket allPublic   # allPublic = no auth needed to download; allPrivate = auth required
b2 create-bucket --bucket-info '{"owner":"matt"}' mybucket allPublic
b2 create-bucket --lifecycle-rules '[{"daysFromHidingToDeleting":1,"daysFromUploadingToHiding":null,"fileNamePrefix":"chunks/"}]' mybucket allPublic
b2 create-bucket --default-server-side-encryption SSE-B2 mybucket allPublic
b2 get-bucket mybucket                # full bucket info as JSON
b2 get-bucket --show-size mybucket    # also include totalSize in bytes
b2 update-bucket mybucket allPrivate  # e.g. flip public -> private
b2 delete-bucket mybucket             # bucket must be empty first (watch for leftover .DS_Store from sync --delete)
```

## Uploading & downloading files
```bash
b2 upload-file mybucket ./local/notes.txt notes.txt                            # bucketName, localFilePath, b2FileName
b2 upload-file --content-type text/plain mybucket file.txt file.txt
b2 upload-file --info hello=matt --info owner=matt mybucket file.txt file.txt  # custom fileInfo key=value metadata
b2 download-file-by-name mybucket test.pdf downloaded-test.pdf                 # download by bucket + name
b2 download-file-by-id <fileId> download.pdf                                   # download by fileId (get id via `b2 ls --long`)
b2 get-file-info <fileId>                                                      # metadata for a stored file
b2 copy-file-by-id <sourceFileId> destBucket newpath/file.txt                  # server-side copy, no download/reupload
b2 hide-file mybucket file.txt                                                 # soft-delete: adds a hide marker, keeps older versions
```
Files >= 200MB are auto-uploaded as large files in parallel parts (10 threads by default; override with `--threads N`, part size with `--min-part-size`).

## Listing & searching
```bash
b2 ls                                  # no args: list all buckets
b2 ls b2://mybucket                    # top-level contents of a bucket
b2 ls b2://mybucket somefolder         # contents of a specific folder
b2 ls --recursive b2://mybucket        # everything, including nested folders
b2 ls --long b2://mybucket             # + fileId, upload date/time, size
b2 ls --long --versions b2://mybucket  # + all historical versions of each file
```

## Deleting files
```bash
b2 delete-file-version <fileName> <fileId>  # delete one specific version (fileName optional but faster with it)
b2 rm b2://mybucket                         # deletes most-recent version of every top-level file (use with care)
b2 rm --recursive b2://mybucket             # + child folders
b2 rm --recursive --versions b2://mybucket  # + ALL versions, effectively wipes the bucket
b2 cancel-large-file <fileId>               # abort one stuck/unfinished large-file upload
b2 cancel-all-unfinished-large-files mybucket
b2 list-unfinished-large-files mybucket     # find fileIds worth canceling
```

## Syncing
```bash
b2 sync ./localdir b2://mybucket/dir                                                   # upload: local -> bucket
b2 sync b2://mybucket/dir ./localdir                                                   # download: bucket -> local
b2 sync --dry-run ./localdir b2://mybucket/dir                                         # preview without transferring
b2 sync --delete --replace-newer ./localdir b2://mybucket/dir                          # make destination EXACTLY match source
b2 sync --keep-days 30 --replace-newer ./localdir b2://mybucket/dir                    # mirror, but keep old versions 30 days
b2 sync --allow-empty-source --delete ./emptydir b2://mybucket                         # wipe a bucket clean via sync
b2 sync --exclude-regex '(.*/Screen Shot)|(.*/.DS_Store)' ./localdir b2://mybucket/dir
b2 sync --compare-versions size --compare-threshold 1000 ./localdir b2://mybucket/dir  # ignore <1000-byte size diffs
```
Sync always needs one local path and one `b2://` path — it can't sync local-to-local or use plain bucket names on the v4+ subcommand form. `--compare-versions {none,modTime,size}` controls what "unchanged" means (default `modTime`).

## Sharing / URLs
```bash
b2 make-url <fileId>                                             # permanent "native" download URL for a fileId
b2 make-friendly-url mybucket file.txt                           # human-readable download URL (bucket + name)
b2 get-download-auth mybucket                                    # auth token for downloading from a private bucket
b2 get-download-auth --prefix folder/ --duration 3600 mybucket   # scoped + time-limited token
b2 get-download-url-with-auth mybucket file.txt --duration 3600  # pre-authorized URL, valid for N seconds
```

## Keys
```bash
b2 create-key newKeyName listBuckets,readFiles                                   # comma-separated capabilities, no spaces
b2 create-key --bucket mybucket --duration 86400 scopedKey readFiles,writeFiles  # bucket-scoped, expires in 24h
b2 list-keys                                                                     # keyId + name only
b2 list-keys --long                                                              # + bucket/prefix restriction, duration, capabilities
b2 delete-key <applicationKeyId>
```

## Object Lock (legal hold & retention)
```bash
b2 update-file-legal-hold <fileName> <fileId> on                           # prevents deletion until turned off
b2 update-file-legal-hold <fileName> <fileId> off
b2 update-file-retention --retain-until 1704096000000 <fileId> governance  # lock until epoch-millis timestamp
b2 update-file-retention --bypass-governance <fileId> none                 # requires bypassGovernance capability to shorten/remove
```
Requires `fileLockEnabled=true` on the bucket. `compliance` mode can never be shortened by anyone; `governance` mode can be overridden with `--bypass-governance` plus that capability on the key.

## Useful one-liners
```bash
b2 ls --long b2://mybucket | awk '{print $1}'                            # grab fileIds for scripting deletes/copies
b2 sync --dry-run --delete ./localdir b2://mybucket/dir                  # see exactly what a destructive sync would remove, before running it for real
b2v3 update-bucket --bucketInfo '{"pizza":"yummy"}' mybucket allPrivate  # fall back to b2v3 to use old camelCase flags / bare bucket names
```
